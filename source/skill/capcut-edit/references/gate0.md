## Stage 1 — delivery and audio

Read the current ask and retained answers before intake. If the output is unresolved, include this choice in the existing missing-input question: edit/add captions directly in the named CapCut project (`EDIT_TIMELINE`), or only create a subtitle file (`SRT_ONLY`). Use the user's language and concrete choices; do not add a separate generic approval menu. A clear prior request to add captions to a timeline already answers the choice; reuse it. File delivery does not authorize project writes, and receiving audio or encountering an app blocker never silently replaces a timeline request.

When speech must be transcribed and no sufficient usable audio is available, proactively ask the user to export/provide an audio file with the other consequential missing facts. For captions on an existing edited clip, request the audio exported from that exact current timeline, from its beginning through the intended end, with its pauses, clip joins and speed changes retained. Bind the selected export range and any start offset. If original-source audio is supplied instead, bind its source clock and the reviewed edit map before assigning timeline timestamps. Do not ask for another export when authorized available media already provides reliable audio, or when a valid aligned transcript/audio source has already been supplied.

Record `output.mode`, its evidence, and `audioInput` identity/hash, duration, clock basis (`EDITED_TIMELINE`, `ORIGINAL_SOURCE`, `AUDIO_FILE` or unresolved `UNKNOWN`), export range, start offset and timing evidence in the task brief. Audio-file-only SRT uses the supplied file clock. A matching duration or filename is a consistency check, not sufficient evidence that an audio export has the correct range/offset. Ask one targeted follow-up only if the remaining clock ambiguity changes correctness. Do not upload private audio, install a transcriber, spend money, or assume new tool authority. Continue authorized local preparation while the missing source blocks only transcription/alignment.

For `SRT_ONLY`, the finish line is the file-and-audio done test in [Content and captions](content-captions.md); typography/style and native project acceptance are not required for a file-only claim. For `EDIT_TIMELINE`, retain the existing native playback, one-line appearance, independent caption-object and save/reopen proof. A text line in SRT is not proof of one visual row in CapCut. Unknown audio wording/timing keeps the affected file draft; receiving a file never proves personal listening or correct transcript.

## Brief

For speech CONTENT_EDIT, bind the default audio-first checkpoint without asking
the user to choose it again: cut, send the checked full listening copy, resolve
feedback, accept that exact audio, then native caption/picture review and
edit–save–close–reopen. Native application waits for the current audio decision;
offline preparation does not. Bind the full remaining true quiet cap of200000
microseconds and contextual hesitation removal. Record meaningful/quoted speech
and unresolved source islands separately; the content leaf owns this procedure.

For EDIT_TIMELINE, first apply [project identity](project-identity.md): distinguish NEW creation from existing lookup/revision, retain a verified existing name literally, and validate supplied NEW names against the underscore/style-context-episode contract. Default an unspecified prefix to the selected style name, allow optional evidenced middle context, and end with the episode number/title rather than draft/review/fb state. Reuse known answers; ask only missing style/episode facts or a real explicit-name conflict. Bind lookup/creation state separately; new tasks use agent creation when eligible rather than asking the user to create a blank draft. A route acknowledgement or naming pattern is not an existing project, closed editor, native FPS or playback proof. SRT_ONLY adds no project-name dependency.

Fill the task-owned instance of `templates/brief.json`: outcome/audience, script role and required spoken units, target format, content checkpoint, optional later B-roll, latest-usable rule, caption timing tolerance, readable-size floor and safe width. Record facts, accepted choices, assumptions and unknowns separately. Bind the default caption policy: one visible line, at most six displayed words within one reviewed logical sentence, aiming for five or six only when meaning permits. Preserve internal reviewed commas, colons and question marks; remove cue-ending commas and ordinary full stops; invent no punctuation except the explicitly authorized reviewed ordinal-prefix period. Keep ordinary words lowercase with verified names preserved, and each end equal to the next start. Bind reviewed sentence IDs and contiguous raw word ranges before display formatting; transcription segments and punctuation alone are not sentence proof. Bind retained user-lock references and contextual recognition/review on raw logical sentences before word-count packing; inspect both sides of legal boundaries and rerun all retained/new locks after repairs. Bind whole-transcript semantic review plus typed reviewed protected raw spans for indivisible noun, adjective and verb phrases, names, terms and number-unit expressions within those sentences. No packing target may split those spans; document genuine over-limit conflicts and distinguish longer compositions with reviewed constituent splits. For explicitly authorized, reviewed spoken lists, replace only the bound ordinal marker and reviewed lead-in with a numbered prefix such as `1.`; retain every consumed raw word ID in reversible transformation evidence. Keep the prefix with its first content word in one cue, capitalize only that word’s first character, then retain ordinary lowercase and verified-name case. This period after the reviewed ordinal is the only default added/full-stop exception; never infer a list, delete other words or change source audio. Validate complete list order and exact lead-in wording before conversion. First onset and last reviewed end remain reviewed boundaries. Bind each cue first raw-word onset to the final edited audio/source map with evidence, then freeze the onset tuple before END-only holds. ASR intervals containing leading quiet or an inherited gap-filled clock do not certify the true start. Never pull the next start earlier to fill a gap; unresolved onset estimates keep timing acceptance pending. Carry every previously user-requested or accepted protected span forward as a hard constraint in each regrouping; never remove or redefine it just to make a proposed boundary pass. Recheck all retained and new spans after every repair; only a newer explicit scoped user decision may supersede an accepted assertion, with its history and reason preserved. Include contextual auxiliary/modal verb units such as sẽ là, có thể, không thể or đã từng when reviewed as one unit; protect the full reviewed expression rather than banning a bare word or forcing every occurrence into the same grouping. Only a future explicit user request can override these caption conventions; record its scope/evidence, not merely a style preset. Keep name verification and numeric meaning conversions as task data. Reuse known answers; never restart intake because a leaf is selected. Ask one targeted question only when correctness, cost, access, permission, destination or done changes. Exact wording and approval are different things.

Bind `pacingScope: ALL_PAUSES` by default for authorized `CONTENT_EDIT`, including quiet at the head, inside phrases/between sentences, and at the tail. Bind `pauseCriterion = {minimumQuietDurationTicks: 200000, comparison: "STRICTLY_GREATER", auditScopes: ["HEAD", "INTERNAL", "TAIL"]}`. Compare the full reviewed real quiet duration, not contained frame count: only intervals strictly over 200ms qualify; at/below stays unchanged unless separately authorized. It is a detection threshold, not a command to retain 200ms or cut into speech. Bind source/audio/phonetic-handle and join review before removing any interval; unknown or risky quiet holds that interval with a specific boundary/source diagnosis. Audit all three scopes; an unreviewed head/tail must not disappear from the report or yield an all-pauses-complete claim. A different explicit task choice may select `INTER_SENTENCE_ONLY` (preserve intra pauses, legacy sentence tail) or `SENTENCE_AND_INTRA` (legacy 15/5). Bind `pacingScopeOverride = {pacingScope: <selected legacy scope>, authority: "explicit-user-request", evidenceRef: <nonempty scoped user evidence>}`. Do not reuse a historical preference as the current default or silently experiment on an accepted primary edit. Preserve source bounds, normal speed and actual native timeline FPS in every mode. Subtitle-only/SRT-only/edited-export transcription is excluded from recutting. Reuse known answers; unknown quiet is an evidence dependency, not a reason to restart intake.

Bind B-roll `coverageMode: SPARSE` unless a voiceover-reading presentation and full picture coverage are explicitly established. For `FULL_TIMELINE`, record `sourcePresentationRole: VOICEOVER_READING` with reviewed coverage evidence, then plan a contiguous picture layer from zero to the full timeline end. First/last picture-edge exceptions do not alter true caption starts or the last reviewed caption end. Keep the underlying voice/cuts, source classification and native acceptance separate; full picture coverage is not permission for a main-video edit.

For B-roll, bind the frozen current base and whole-timeline `sourceUsageReview`, including unchanged placements and verified SHA-256 aliases. Plan fresh suitable sources/windows first; overlapping source reuse needs at least three target minutes from every previous overlapping END to the new START, plus per-placement exhaustive eligible-unused-window review under [B-roll](b-roll.md#source-usage-fresh-footage-and-conditional-reuse). Reuse known material facts; ask the existing interview only for a consequential missing source/eligibility fact. Unknown inventory or exhaustion holds the affected slot, not permission to improvise irrelevant/full-cover filler. Do not retroactively edit or certify an accepted project under a newly adopted rule.

For a user-facing voice/listening review, bind `voiceReview.linearGain: 2.0` and read the content leaf's listening-copy section before export. This doubles signal amplitude, not playback speed or the source/main-project volume; record gain, identities, duration and clipping readback.

## Material

Inventory source identity/hash, duration/frame-rate/rotation, source chronology, main speaker and prompter/other roles, references and rights. Recording chronology needs evidence; modified-file time alone is insufficient. Supplied captions, draft JSON and model output are references until words, speaker and timing are checked against the actual source audio. Do not trust stale, zero/negative or overlapping word durations. Private inputs remain task data, outside reusable skill assets.

Bind `script.mode` before source selection: `EXACT_CONTENT` means the supplied script is a content requirement, while `REFERENCE_ONLY` means an image/script guides preparation without overriding the selected recording. Reuse an explicit user decision. Otherwise default supplied scripts/images to `REFERENCE_ONLY`, bind the skill-default evidence, and prioritize reviewed actual recorded speech. Do not ask the user to choose exact versus reference-only merely because a script/image was supplied. Select `EXACT_CONTENT` only for an explicit user requirement to follow its words verbatim; if that conflicts with a newer explicit direction, resolve only that conflict. A script or image cannot silently replace, correct or fabricate the recorded words. For reference-only work, retain reference identity and evidence separately, bind reviewed actual spoken units and exact raw word IDs, and never label them an exact match to the reference. A user-selected source identifies the requested input; it does not authenticate every audible word, speaker, latest take or trim.

Before source reuse or take selection, bind the requested hook and the script/topic according to that role to the actual recorded speech. Record the candidate media identity/hash, actual duration/FPS/rotation, spoken-hook range, disambiguating script-unit matches, source clock and match evidence. A project display name, episode number, directory label, matching XML duration or an inherited caption transcript is not proof of the requested topic. Do not overwrite an existing named project or copy its caption content merely because its name resembles the target. Local ASR may shortlist candidates, but model matches remain provisional until source wording, speaker and timing are checked; reject a demonstrated wrong-topic source and continue within the authorized material scope. For no-script subtitle work, bind the supplied edited audio/project identity and clock instead of inventing an exact-script prerequisite. Missing source truth holds its dependent edit without creating new tool or scanning authority.

## Style

Ask “Clip này làm cho ai?” when the recipient is unknown, and reuse an already evidenced answer. Bind recipient.kind PERSON, recipient.id mrs-nga and a reviewed person identity plus contentDomain.id real-estate with separate evidence. A bare Nga, country, filename, topic or speaker does not establish that client. If Mrs Nga is confirmed and only the domain is unknown, ask the consequential domain question in the existing interview. Preserve an explicit different selected style; otherwise the two confirmed facts select the existing nga profile. Other clients/domains do not inherit its exact display emoji rules. The content leaf owns matching/raw-ID reversal; selecting the saved rule is not font calibration or native appearance proof.

Offer existing applicable saved profiles plus a task-specific choice. Reuse a selected style instead of asking again. Load `styles/nga.json` only when Nga is selected. Reuse its privacy-safe USER_ACCEPTED_PORTABLE_BASELINE visual parameters without restarting the reference interview, and populate a task-owned instance. Its `PENDING_FOR_TARGET_RUNTIME` calibration state still requires current installed-font identity, width/readability, native glyph/style and save/reopen proof; old project acceptance is not a transferable render PASS. Resolve font, readable size, color, border/background, position, available width, aspect ratio and phrase behavior. Keep reference calibration, actual font availability and native appearance separate. A pending profile can guide preparation; it cannot be called a calibrated style.

Future saved styles use the same safe parameterized shape. Do not silently create a persistent style from private client facts; reusable profile mutation follows the owning instruction/style change gate. Do not copy source images, fonts or templates without the relevant rights/authority.

## Exit

Bind native review mode as well as output mode. FINAL_ACCEPTANCE remains the default.
Only an explicit current-task choice of the controlled review workflow permits
REVIEW_DRAFT at its exact destination: CREATE_SEPARATE_NEW_PROJECT for a new
project, or READDRAFT_UPDATE_OWNED for the explicitly bound existing task project
with its immutable baseline/identity and current bytes. List all unknown
content/take/quiet/onsets and read the [native pipeline](native-pipeline.md#controlled-review-draft)
before that apply. Reuse known user decisions. A draft label does not authorize
source guessing, accepted/foreign-project overwrite or a final quality
claim from provisional preparation.

Editing starts only when source scope, script role and required spoken units for content editing, applicable take/speaker rule and destination are sufficient for that step. Font or native-proof gaps can leave text/map preparation ready while style/native acceptance remains pending. Bind the chosen method and known gaps to the task brief, then load `content-captions.md`. Keep existing authorization; no renewed continuation menu is needed for ready work.

Only in an explicitly selected legacy 15-frame-tail mode, for actually reviewed preceding-source quiet shorter than that target, only a scoped explicit user decision permits keeping that real quiet and reporting each short sentence. No inferred ASR/energy/UNKNOWN shortfall, freeze or padding. Distinguish projected full auditory gap microseconds from contained whole quiet frames and both fractional speech-edge margins. Preserve original microsecond word/source pieces. A native representation conflict holds the affected join with partial prepared status; it does not erase valid independent preparation or certify the final pace.
