## Source identity before take selection

Match the actual spoken hook and disambiguating required content to the requested edit before reusing a take or a named project. Default supplied scripts/images to `REFERENCE_ONLY`, using their topic/order as reference while preserving reviewed actual speech. Do not restart an exact-versus-reference interview. Use `EXACT_CONTENT` only when the user explicitly requires verbatim script wording; a real conflict between explicit instructions may still need a targeted question. Bind `script.mode`: `EXACT_CONTENT` compares the supplied script units exactly; `REFERENCE_ONLY` keeps that reference separate and uses reviewed actual spoken units as the content authority. Never substitute reference-only words for the selected recording or pass different spoken units as an exact script match. Reuse a direct user source selection as input identity evidence while keeping lexical, speaker and trim review separate. Bind media identity/hash, audio/source clock, match ranges and evidence. An episode number, directory label, same project name, XML recording metadata or inherited caption body cannot establish the topic. A verified mismatch rejects that candidate even when its filename looks right. Search only the already authorized source scope; do not replace missing speech with another episode or copied script captions.

ASR is a candidate supplier. Keep its lexical matches, speaker assignment and word boundaries provisional until checked against actual source audio; a match does not prove every word, the latest usable take or a clean trim. Preserve exact raw text, names, numbers, negation and the existing script-variation gate. For no-script subtitle-only work, bind the supplied edited audio/project identity and clock rather than forcing new take selection or an invented script.

## User-facing listening-copy gain

Before sending or rendering any user-facing voice/audio review, create a separate copy at **linear gain 2.0** (+6.0206 dB). Keep sample rate, channels, sample count, duration, speed, order and source-to-review map unchanged. Never apply this review-only gain to original media, selected source speech, the main CapCut audio track or final export by implication. Existing accepted wording/selection stays accepted at its recorded evidence basis; a gain-only copy is not a new content decision or personal hearing proof.

Use `scripts/prepare_voice_review.py --input ABSOLUTE_PCM16_WAV --output NEW_ABSOLUTE_WAV` for decoded uncompressed 16-bit PCM WAV, through existing task-owned placement guards. The helper creates a review copy and a hash-bound `.review.json` readback with exact 2x sample proof; no installation, source upload, app-store write or hearing claim follows. Resolve other formats with existing authorized local decoding before this helper; retain source identity and clocks. Never send the unboosted copy as the default review or silently normalize the gain back to 1.0.

For a short diagnostic listening excerpt, include complete neighboring words and enough source context on both sides. Do not start it at an arbitrary time inside a syllable. Bind the excerpt's offset to the full candidate and check whether a reported defect exists in the full candidate, only at the excerpt edge, or both before changing the main cut. Preserve that distinction in the feedback record; a truncated demonstration must not cause an unrelated main-audio repair.

Preflight both positive and negative peaks. If doubling exceeds PCM bounds, the helper refuses before writing. Hold only that export for a verified clipping-safe representation or an explicit scoped exception; do not silently clamp, attenuate, change words/timing or call a distorted copy accepted. A tool/data PASS proves gain/sample identity only; actual listening and native acceptance remain separate.

User feedback that identifies a defect is not acceptance. A generic continue, Teacher package approval, ASR result, draft label or successful helper cannot substitute. Task-local transcript/caption/B-roll planning and compilation may continue while waiting; their timing-dependent outputs must be rebuilt after a recut.

Before closing that first audio review, compare the stable assembled candidate's actual spoken-content transcript with the proposed retained words, using an exact-candidate local transcription when needed. Investigate unrepresented speech islands, repeated/restarted phrases, missing words and source-model words allocated across long or discontinuous voiced regions; raw-ID coverage alone cannot establish audible coverage. Keep model differences provisional and review source context rather than deleting or adding speech automatically. Do this early enough to reduce avoidable user review rounds. Reuse the same transcript/alignment after acceptance when its exact audio identity is unchanged; do not mandate another full transcription. A recut refreshes affected source/output clocks and boundary review.

Bind a task-owned audioReviewCheckpoint to exact analysis/project gain1 audio, listening-copy bytes and gain receipt, source-to-edited clock/map, latest feedback inventory and real user decision. Preserve the actual message/reference and distinguish mechanically binding that observed decision from inventing approval. Every current audio defect must have a disposition on this revision. A changed audio cut, spoken word, gain, offset or actual source-sample clock invalidates the prior checkpoint; unchanged exact accepted audio does not require the same question again. For this checkpoint, user acceptance proves the scope actually reviewed, not personal model hearing or every native caption onset. Caption/picture review and editable save–close–reopen happen afterward in CapCut. A verified silent-content exception needs explicit source classification; SRT_ONLY never acquires a native requirement from this step.

Caption-only or verified same-byte media-reference changes may alter a plan's
native IDs/path metadata and clock-map wrapper hash without changing accepted
audio. Reuse that actual user decision only when gain1/listening-copy identities,
resolved-feedback inventory, task and direct AUDIO_CONTENT reply/quote remain
identical, with the current checked gain receipt still valid. Preserve the old
binding as an immutable hash-bound input and use the owned preparer's
[exact-audio binding procedure](native-pipeline.md#controlled-review-draft).
Never rewrite prior acceptance, invent another user reply or label the mechanical
binding as fresh hearing. The independent fresh native/source-to-audio guard

Any new audio hash requires actual review/acceptance of that new version before

failure blocks this reuse; preserve the real unresolved defect instead of
rebinding around it. Unchanged audio acceptance does not carry native caption
onset, appearance, editability or save/reopen proof into a changed revision.
Refresh affected current proof under the existing rules; this is neither a new
permission gate nor a waiver of the audio-first sequence.

## Contextual filler disposition

Remove nonlexical hesitation sounds such as ừm/ờ during content editing when their actual role is reviewed as filler. Do not delete every matching spelling: retain meaningful affirmative replies, quoted demonstrations, names and lexical words such as ở. A detector may omit a voiced filler, and a word model may stretch the next content word across it. Inspect full source context, waveform/detector candidates and actual listening; ASR absence never proves a source island is quiet or harmless.

Inventory each candidate by original source identity/range, current output position, neighboring content words, actual role evidence and attachment: isolated between two speech-free intervals, attached to adjacent content, or unknown. A detectably nonlexical filler standing alone between two pauses must be removed; its absence from ASR is not permission to leave it. For an attached filler, attempt a local boundary only when full adjacent speech can be retained. If separating it risks a syllable or consonant, retain the attached sound as HELD_FOR_PHONETIC_SAFETY with its exact range, reason and current user feedback; do not treat that disclosed safety hold as an isolated-filler exemption. Unknown role/attachment stays pending. Keep removed hesitation, meaningful/quoted speech retained, attached safety hold and unresolved unknown distinct. Keep original ASR and take history immutable. If a removed filler has raw IDs, retain them in a separate explicit rejected-word/occurrence record with the reason and exact source cut; regenerate the retained sentence/cue inventory. If ASR omitted the sound, record an unmapped acoustic source island instead of inventing a word ID or hiding it in a quiet cut. Preserve the full adjacent content syllables and a clean join. Inspect the complete first consonant after the join, including quiet unvoiced onset before the louder vowel; a loud peak or an ASR word start alone cannot locate it. Compare a short before/after context at normal speed. If the new join clips speech, restore the necessary earlier source handle, rebuild its exact clock and recheck; do not mask the loss with captions, gain or a crossfade. Respect any user limit on local attempts and report a remaining safety hold instead of repeatedly shaving the same word. Filler removals and joins remain provisional until current audio feedback clears them; model word/onset timings still require their separate review. After removal, rebuild source/output mapping, caption STARTs, END-only holds and dependent B-roll; recheck the entire audio for analogous fillers and repeated tails.

## Take selection

Read [Repeated ideas and usable takes](take-review.md) before source take selection
or repairing a repeated idea. It owns occurrence coverage, semantic variants,
partial restart chains, last usable full reading and the early candidate audit.

For each required content unit (exact script or reviewed spoken unit according to `script.mode`) review all candidate attempts, including rejected ones. Record source in/out, recording order, main/prompter/other/unknown role, completeness, usability, exact spoken words and evidence. Choose the latest candidate that passes all conditions. A later incomplete, incorrect or unusable take does not supersede an earlier usable one. Silence detection and similarity matching propose boundaries only. If no valid take covers a unit, name the exact missing content; never silently drop it. Reject source speech reused across script units.

### Utterance continuity and repeat disposition

For content editing, resolve complete and partial restarts, repeated phrase attempts and other rejected speech before quiet pacing. Bind each relevant audible occurrence to its actual source context, speaker, source ranges, recording order and task-owned occurrence identity; record ACCEPT, REJECT or HELD with evidence. Keep the latest complete usable main-speaker occurrence and its surrounding meaning. Preserve deliberate rhetorical repetition when it belongs to the accepted speech; a repeated string alone never authorizes deletion or deduplication. Subtitle-only or caption/style scope does not authorize a spoken-content edit.

Compare the actual audible sequence and occurrence counts in source context with the final joined output and selected take, including retained handles or source islands not represented in the supplied word model. Account for those regions as evidenced quiet, accepted speech, rejected restart or UNKNOWN; do not call them quiet or harmless merely because ASR omitted a word. Unique raw IDs, one textual occurrence, nonoverlapping source ranges and a correct source map cannot prove that the output has no extra audible repetition. A human-reported repeat is a defect to resolve, not something those structural checks can overrule. Keep uncertain occurrence identity or multiplicity PENDING rather than inventing phonetic labels.

Treat dense cuts within a protected spoken phrase, short isolated source pieces and jumps between partial word/phrase legs as review risks. Inspect the complete phrase through every source leg and join at normal speed, including neighboring context, to check phonetic continuity, repeated tails and missing or fused syllables. Prefer a complete usable occurrence over stitching incompatible retake fragments when available. Neither cut count alone nor caption text protection proves a defect: valid reviewed quiet-only cuts may remain inside an atomic cue. Do not impose a universal cut-count limit or merge across removed material without review.

A proposed quiet hole inside one modeled word is a partial-phoneme risk even when nonempty word legs survive on both sides. A later ASR still recognizing that word does not prove the splice retained its full sound. Check that exact source hole and joined phrase; if a reported splice is unsafe, restore the necessary original speech and prefer a contiguous usable word/phrase over leaving a chopped reconstruction. Recheck real quiet after restoration; soft speech is not an over-cap quiet interval merely because a detector labeled it so. Keep the source cause, before/after sample map and scoped listening result with the task.

An actual restart/retake correction is a separately evidenced spoken-content edit under its existing authority, never a quiet-only removal. Preserve original source and transcript history, retain ACCEPT/REJECT/HELD occurrence dispositions and reconcile the selected word/source model when actual speech was omitted or misallocated. Do not delete historical raw IDs or silently reinterpret every retained sound as required content. After an authorized change, rebuild the affected selected-word and piecewise clocks, recheck all retained semantic/style constraints, then establish fresh final caption onsets, END-only holds and dependent B-roll anchors with current audio/native persistence proof.

## Audio and script

Check source audio at every candidate boundary and required word. Always preserve exact audible raw words, accents, names, numbers and negation. In `EXACT_CONTENT`, also preserve the exact required script; flag a mismatch and seek a correct take. In `REFERENCE_ONLY`, retain the reference and its role evidence separately and bind reviewed actual spoken units; do not invent reference-word coverage or weaken raw-word fidelity. If the user explicitly authorizes a variation, record its exact scope; do not pass it through the strict helper as an exact match. Revalidate inherited transcript timing before using it. Use approved local transcription/alignment when needed; external processing or a new installer requires separate authority. Keep raw reviewed words and script checks exact. Caption display may remove ordinary full stops and cue-ending commas and change case under the caption policy; authorized reviewed enumeration lead-ins and the applicable saved Mrs Nga real-estate whole terms may use reversible display substitutions without changing audio or dropping raw word coverage. Keep raw wording and reviewed logical-sentence boundaries separate from display formatting; punctuation or a transcription segment alone cannot establish a sentence boundary. Verified names and any numeric conversion are task-owned reviewed data. Voice reviews reader copy; the explicit caption lowercase rule overrides generic sentence capitalization only in captions.

## Final caption onset anchors

The onset and END-hold convention below is the default. An explicit current-task selection of [strict clip-edge alignment](#selected-strict-clip-edge-alignment) changes the reviewed outer END bounds and authorized edge-repair scope, not the requirement for actual word ownership, current onsets or audio acceptance.

After all authorized content/pause cuts are frozen, extract or bind audio from that exact revised timeline (or an evidenced constant-translation source-piece equivalent), including its joins, speed, start offset and full intended range. This is the post-CND anchor stage, not a reuse of the pre-cut transcript clock. Bind current identities/hashes and invalidate obsolete onset/hold/B-roll timing evidence.

Establish each cue start from its first audible raw word on the **final edited audio clock**, including consumed words represented by an authorized ordinal or emoji display transform. Bind the current audio/source identities, retained word IDs, piecewise source-to-native map, onset ranges and evidence. ASR may assign preceding quiet to a word, miss a first word or allocate a word across discontinuous source clips; model confidence and a matching caption string do not certify the true onset. Keep an uncertain or deliberately held boundary labeled `PENDING`; do not invent a replacement time or report personal hearing from ASR.

Resolve an onset repair separately from gap filling. A valid evidence-backed correction may change an existing wrong start, but it must preserve raw text/grouping/style and receive fresh audio/native timing proof; it is never a side effect of closing a gap. Map original word events by constant translation through the final retained pieces, never duration rescaling. Preserve subframe word ticks and disclose actual native frame alignment/tolerance; rounding or padding must not move a caption before the first speech merely to remove a visible gap. Content recuts invalidate prior onset evidence and require a fresh final-clock map.

Freeze the resulting ordered onset tuple before end filling. Set only `END[i] = START[i+1]`; do not alter `START[i+1]`, pull it to the previous end, or overlap two text layers to disguise an early start. Preserve the first reviewed onset and last reviewed end rather than extending the final caption to the timeline end. Read back all starts against the frozen tuple, positive intervals, exact next-start joins, raw-ID/semantic-lock coverage and current derived frame/millisecond/word-hold fields. An END-only pass on already touching but early-starting captions is a no-op, not a repair. The pacing helper emits `captionOnsetStatus: FRAME_ESTIMATES_PENDING_FINAL_AUDIO_REVIEW`, `finalCaptionAnchorAcceptance: PENDING` and `captionStartsUnchangedByEndFill: true`. The last field certifies only that its end-fill step leaves its generated starts unchanged; it does not authenticate those starts or claim that a recut preserved an old clock. Supplying `reviewedFinalCaptionOnsets` to pacing is rejected rather than silently replacing a reviewed tuple. Use the separate final edited-audio anchor stage after pacing, freeze its reviewed onset tuple, then perform END-only holds. Actual audio onset, native one-line fit, editability and save/reopen proof remain separate acceptance requirements.

### Cut-adjacent onset audit

Before accepting final onsets, build a task-owned inventory over **every current cue and main-source cut**, not only user-reported examples. Include a cue that contains, crosses or touches a cut, or whose first raw word interval intersects a retained phonetic handle beside a cut, even if the cue itself does not cross it. Bind the current audio/native hashes, cue/raw-word IDs, all involved source-piece IDs and exact source/output ranges, retained handles, first-word estimate/refinement provenance, and reason for inclusion. Account for every current cue and cut; record non-risk exclusions and missing/ambiguous mappings rather than silently omitting them. Do not use a universal distance or global timing offset in place of the actual source/handle relationship.

Record START and END provenance separately for each inventoried first raw word: before/after source and output ticks, evidence and acceptance status; refining only END must never upgrade ONSET acceptance or exclude an unchanged/uncertain START from the risk audit.

Prioritize the pattern where the first raw word lies alone in the preceding retained piece while every remaining cue word lies in the next piece, especially when that first-word boundary is an unchanged ASR estimate. This is a mandatory high-risk review, not proof that the first word is absent or permission to move the cue to the cut, delete a word or borrow the next word's onset. Preserve lexical identity, reversible ordinal/emoji raw IDs and both source legs. Review every analogous cue, not just the reported pair. A quiet-only cut inside an atomic cue can remain valid with all words retained and a verified onset; crossing a cut alone is not a defect.

Use the recomputed **all-cue** risk inventory as coverage; a handpicked onset shortlist only prioritizes review. A first-word model interval with multiple retained legs, or extending across quiet or an earlier utterance leg, needs source ownership reconciled before choosing its current START. The earliest surviving modeled fragment is not automatically that word's first phonetic event. Inspect the complete accepted word/occurrence through its source context; retain all legs and uncertainty rather than choosing the earliest fragment, clamping to a cut or treating a nonempty intersection as heard proof.

For each inventoried risk cue, inspect the actual first phonetic event in source and final edited-audio context, including both source legs when discontinuous or ambiguous. Check the extraction/audio start offset, effective channel/channel mapping, speed and audio/video sync, then each piece's constant source-to-native translation and disclosed frame phase. Never snap to a cut, first loud peak, ASR segment edge or another cue merely because it produces tidy timing. Correct arithmetic, source-text equality, ceiling-to-frame alignment, a refined/model word boundary, serialized draft/ACK equality or a previous user acceptance cannot establish the audible onset of this revision. If review finds a cut removed a required phoneme, hold the affected onset and resolve that source boundary under the existing content-edit authority before re-anchoring; caption timing cannot conceal missing speech. If first-phoneme, source-leg or audio-clock evidence is insufficient, keep that cue's onset acceptance `PENDING` and name the exact uncertainty; do not mark the inventory complete while an analogous cue is unreviewed.

Retain user-confirmed defects as task-owned positive/negative regression fixtures with their current revision and raw-ID evidence, without embedding project/client paths or timing offsets in this reusable rule. Fixture assertions test recognition, coverage and safe hold decisions, not hearing. Only after the required onset review and any separately evidenced repair, freeze the current onset tuple and apply the existing END-only holds. Recheck all affected cue onsets, derived clocks and dependent B-roll anchors, followed by fresh native audio/timing and persistence proof; no caption convention, source cut or style change is implied by the audit.

Before applying any content/caption revision to the native app store, use [Pre-native apply](pre-native-apply.md). All-pauses review precedes final edited-audio onset review, which precedes END-only holds. Provisional files/listening copies outside the store remain available while evidence is missing. The explicit separate controlled review branch may carry pending native caption onsets only after its required current-audio feedback checkpoint; a DRAFT label alone supplies neither that authority nor acceptance.

## Selected strict clip-edge alignment

Use this mode only for an explicit current-task request to match the first caption START and last caption END to each spoken-content clip's edges, including a long clip with several captions. Bind that decision and distinguish actual native main-clip boundaries from logical meaning groups. Record the real clip IDs/source pieces, ordered owned words and first/last cue IDs. A logical group spanning several flat clips is not a single physical clip: adding a group label or invented `group_id` proves no compound representation or boundary match.

Choose meaningful blocks and reconcile complete word/occurrence ownership before choosing edges. Under the selected content-edit scope, correct only affected actual audio edges while preserving full phonemes, words, accepted content and unaffected material. Do not align START to old quiet padding, add voiceless padding, restore rejected speech, change speed or shave a consonant to obtain equality. If an internal physical cut crosses an atomic phrase, do not split its protected text or declare every such cut a group edge. Report the representation/phonetic conflict and prepare the evidenced resolution under existing authority; an unsupported compound or silent weakening is not a resolution. Keep genuinely unresolved sample/frame or safety conflicts held.

After an authorized edge change, rebuild the exact source/output map and checked listening copy and obtain the existing [current-audio acceptance checkpoint](#audio-feedback-checkpoint) before native apply. Reuse an already consumed scope decision; this mode adds no separate permission gate. Historical audio acceptance does not cover the recut audio. Establish current first-word events on that accepted clock, then freeze the new ordered STARTs. For each actual bound clip, its first caption START and final caption END must equal its reviewed edges; internal captions retain their own first-word onsets. Fill each interior END only to the next frozen START **within that clip's bound caption group** and use its reviewed clip end for the last END. Do not extend an END across a group edge merely to preserve the default cross-clip hold. Recheck raw IDs/locks, positive intervals, actual native geometry and dependent B-roll anchors. Equality is a timing condition, not hearing, one-line or save/reopen proof. Subtitle-only/SRT scope never authorizes an audio-edge edit through this mode.

## Phrase intervals

Review the whole retained transcript for indivisible noun, adjective and verb phrases, proper names, terms and number-plus-unit expressions. Bind each reviewed protected span to contiguous raw word IDs inside one reviewed sentence before display conversion; no cue boundary may split it. Five-to-six-word packing yields to meaning, and shorter meaningful cues or leftovers are allowed, including number-unit or comparison units; never force them into a neighboring cue just to fill a count. Compatible nested or overlapping spans must fit together in one cue. A genuinely indivisible span or overlap union exceeding the active displayed-word ceiling is an evidenced conflict, never permission to abbreviate, drop words, split it silently or shrink text. A longer head-plus-attachment composition may be split only at explicitly reviewed constituent boundaries; it is not automatically an atomic protected span. Supplied review assertions do not prove grammar or heard audio. Include contextual auxiliary/modal verb units such as sẽ là, có thể, không thể or đã từng when reviewed as one unit; protect the full reviewed expression rather than banning a bare word or forcing every occurrence into the same grouping.

Supply `protectedSpanReview` for each selected take with `reviewed: true`, a nonempty `evidenceRef`, `basis: whole-transcript-semantic-review` and every selected raw `wordId` in order. Supply an explicit `reviewedProtectedSpans` inventory; an empty list requires that same whole-transcript review rather than a claim that no review was needed. Each row has a unique `id`, `sentenceId`, contiguous `wordIds`, exact raw `text`, `kind` (`noun-phrase`, `adjective-phrase`, `verb-phrase`, `proper-name`, `term` or `number-unit`), `reviewed: true` and evidence. Bind raw ranges before punctuation/case/numeric display changes; never substitute display text for the raw assertion. Validate the entire retained transcript, not only reported examples. Compatible overlap is allowed, but its union inherits the word ceiling. Count displayed tokens after any reviewed numeric expansion. Do not infer protected units automatically or certify completeness of semantic review from the helper alone. Carry every previously user-requested or accepted protected span forward as a hard constraint in each regrouping; never remove or redefine it just to make a proposed boundary pass. Recheck all retained and new spans after every repair; only a newer explicit scoped user decision may supersede an accepted assertion, with its history and reason preserved.

Before removing punctuation, supply `reviewedSentences` for each selected take: unique logical sentence IDs, contiguous raw `wordIds`, exact raw `text`, `boundaryBasis: reviewed-logical-sentence`, and review evidence. These ranges partition every raw word in order exactly once. A transcription/ASR segment ID is not a logical sentence ID; no automatic punctuation-only inference or six-word filling across sentences is allowed. Each reviewed cue declares its `sentenceId`, contiguous word IDs, raw exact text and fresh source start/end, and contains words from that sentence only. Default to at most six whitespace-separated displayed words, aiming for five or six only where that sentence meaning permits; a short remainder is allowed. Genuine short sentences may have short cues without becoming artificial word-by-word fragmentation. Build short cue groups from reviewed words and timing, never by uniform duration, a hard character limit, or invented word times. Never generate word-by-word cues or a second row. Preserve every raw word ID in its original order exactly once; only explicitly authorized reviewed enumeration lead-ins and the recipient/domain-bound saved-style emoji terms below may use reversible display substitutions. A cue crossing removed speech/content material must be resegmented and retimed at the actual join. The reviewed quiet-only cut exception in the pacing section preserves an atomic cue and maps every word piece separately; it never permits removed words or a stale clock. At normal speed, source event `w` in a retained interval beginning at `s` and output beginning at `t` maps to `t + w - s`.

For explicitly authorized, reviewed spoken lists, replace only the bound ordinal marker and reviewed lead-in with a numbered prefix such as `1.`; retain every consumed raw word ID in reversible transformation evidence. Keep the prefix with its first content word in one cue, capitalize only that word’s first character, then retain ordinary lowercase and verified-name case. This period after the reviewed ordinal is the only default added/full-stop exception; never infer a list, delete other words or change source audio. Validate complete list order and exact lead-in wording before conversion.

Retain reviewed internal commas, colons and question marks; never add other punctuation automatically. Remove every ordinary full stop, including abbreviations, and remove a comma at each cue end. A verified dotted name uses its reviewed undotted form. Do not capitalize a cue merely because it begins a cue; lowercase ordinary words and restore only verified names in their proper case, including names spanning adjacent cues within the same logical sentence. Do not combine a name across a sentence boundary. Preserve numeric values and units. An internal numeric comma can remain unchanged; a full stop between digits cannot be stripped blindly and needs an evidenced reviewed conversion preserving the exact numeric meaning and units. Otherwise reject that cue and request the exact numeric meaning. Plain numbers and a trailing sentence full stop are safe under this rule. A reviewed numeric display must satisfy the active punctuation policy and displayed word limit; never silently turn an ambiguous dotted number into another value.

Under the default convention, after establishing and freezing final-clock onsets under [Final onset anchors](#final-caption-onset-anchors), set only each caption end to the exact next frozen caption start, including between source clips; end filling never changes a start. Preserve the first reviewed onset and last reviewed end; do not extend the last caption to the full timeline without review. Keep original source handles, raw word times and content cuts unchanged unless a current explicit content-edit decision selects [strict clip-edge alignment](#selected-strict-clip-edge-alignment); then use its changed-audio checkpoint and within-clip END bounds. Check hold intervals, fractional milliseconds and audio/video joins in the actual native project. Future explicit user requests may override caption conventions in the task brief; a saved style name alone cannot override them.

## Recognition before segmentation

Recognize meaning in the raw retained transcript before stripping punctuation, applying display transformations or filling word counts. A model or reviewer makes a contextual judgment; the helper validates the supplied raw-ID locks and coverage, not an automatic grammatical parse, authentic review or heard source. Start with the reviewed logical sentence and read its adjacent sentence when pronouns, comparisons, contrast or recipients need context. Load every previously user-requested or accepted protected expression before any proposed regrouping. Keep its exact words, raw IDs and review decision; a correction must not quietly redefine or remove an accepted lock.

Review these families across the whole transcript, not only the reported defect. Preserve precise reviewer-family and semantic-relation evidence in task data. The helper's existing `kind` is a transport category: `verb-phrase` for reviewed predicates/modal units, `adjective-phrase` for reviewed adjective/comparison units, and the existing noun/name/term/number-unit categories as applicable. Carry a reviewed fixed functional expression as the existing `term` kind with its raw IDs, contextual relation and evidence; do not extend the closed enum. A generic reviewed unit carried as `term` does not certify an established English expression, named entity or automatic grammatical parse.
