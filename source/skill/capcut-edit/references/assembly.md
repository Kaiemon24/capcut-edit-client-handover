## Shared draft index precision

Before any filesystem mutator that may rewrite shared `root_meta_info.json` (including CLI register, init or rename), inspect original numeric tokens with a precision-safe parser before JavaScript parsing. Integers outside JavaScript's safe range (`abs(value) > 2^53 - 1`) forbid raw `register --apply` or another whole-index JavaScript rewrite. `JSON.parse` can round them before `JSON.stringify`; a replacer or backup alone cannot prevent loss. Keep opaque identity values and their numeric/string types exact, without printing private values. A dry-run or `ok` flag does not establish preservation.

Use only an already authorized compatible precision-preserving writer or exact new task-entry insertion. Close the editor, resolve its real store, check destination/ID/name collisions, and take scoped backups. Change only the named task entry; preserve every unselected row's bytes, values/types and order plus root headers. For a new entry, retain the entire original array body byte-for-byte. Compare current bytes with the planned baseline immediately before an atomic write; drift blocks without overwriting foreign content. Never force-write, initialize a guessed root, change ID types, patch/install a tool or broaden targets as a fallback.

Before reopening, require exact before/after readback of the original rows and headers, the single authorized task entry, unchanged timeline/media references and declared sidecar-only changes. An unexpected unrelated delta requires scoped reconciliation or owned rollback before retry, followed by fresh readback. Report field names/counts and hashes rather than private values. Registration proof remains separate from native playback, editable objects, caption fit and save/reopen acceptance.
